Provably Fair System

Social Teen Patti — How we prove every hand is fair, and why no competitor can match it.

The Problem

Every major Teen Patti app faces the same accusation from its users: "The game is rigged."

Teen Patti Gold, the market leader with 200M+ downloads, has a 1.7/5 rating on Trustpilot with 75% one-star reviews. The dominant complaint: the app manipulates card dealing to force chip purchases.

Whether these accusations are true is irrelevant. What matters is that no existing app can prove they're false. They ask users to trust them. Users don't.

Our Solution: Provably Fair

Social Teen Patti uses a cryptographic commitment scheme that makes it mathematically impossible for us to manipulate card dealing. Every hand can be independently verified by any player, using standard cryptographic tools.

The core guarantee: The deck order is determined before any cards are dealt, locked with a cryptographic hash, and cannot be changed after the game begins — even by us.

How It Works

1

Server Seed Generation

Before each hand, the server generates a cryptographically secure 256-bit random seed using Node.js crypto.randomBytes(32). This seed is unpredictable and cannot be reverse-engineered.

2

Deterministic Shuffle

The server seed is used to deterministically shuffle the 52-card deck via HMAC-SHA256 chain. The shuffle uses the Fisher-Yates algorithm, where each random index is derived from HMAC-SHA256(seed, index). The same seed always produces the same deck order.

3

Hash Commitment

The server creates a SHA-256 hash of: serverSeed + ":" + deckOrder + ":" + nonce. This hash is sent to all players before any cards are dealt. It appears as the "Provably Fair" badge in the game header.

4

Game Plays Normally

Cards are dealt from the pre-committed deck. The server cannot change the deck order because any change would produce a different hash — and players already have the original hash.

5

Verification

After the hand ends, the server reveals the serverSeed and the full deckOrder. Any player can compute SHA-256(serverSeed + ":" + deckOrder + ":" + nonce) and verify it matches the hash they received before the hand started.

Client-Side Verification Code

Players can verify fairness using this JavaScript function, which runs entirely in the browser:

async function verifyFairness(serverSeed, deckOrder, nonce, expectedHash) {
  const data = serverSeed + ':' + deckOrder + ':' + nonce;
  const encoder = new TextEncoder();
  const hashBuffer = await crypto.subtle.digest('SHA-256', encoder.encode(data));
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  const hash = hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
  return hash === expectedHash;
}

// Returns true if the hand was fair, false if it was tampered with.

This function uses the Web Crypto API (available in all modern browsers). No server calls are needed — the verification is completely independent.

Optional: Client Seeds

For additional security, players can contribute their own seeds before each hand. The final shuffle uses HMAC-SHA256(serverSeed, clientSeeds.join(':') + ':' + nonce). This ensures that even the server alone cannot predetermine the outcome — at least one player's seed adds entropy that the server cannot predict.

Why Competitors Can't Copy This

Retrofitting a provably fair system into an existing app requires:

  • Rewriting the game engine to use deterministic shuffling (not Math.random())
  • Adding hash commitment infrastructure to every game session
  • Building client-side verification UI
  • Implicitly admitting the current system isn't verifiably fair

The last point is the real barrier. No incumbent will voluntarily announce "we're adding provably fair because our current system can't be verified" — it validates every user who ever said "the game is rigged."

RNG Quality

Our random number generation uses crypto.randomInt() from Node.js, which sources entropy from the operating system's CSPRNG (Cryptographically Secure Pseudo-Random Number Generator). This is the same quality of randomness used by:

  • Banking and financial systems
  • SSL/TLS encryption
  • Online poker platforms (PokerStars, GGPoker)
  • Government lotteries

We are pursuing third-party RNG certification from iTech Labs or GLI (Gaming Laboratories International) to provide independent validation.
